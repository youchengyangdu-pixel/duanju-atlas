02最值得搬：breakdown 的 7 步工作流

这就是一套现成的拆解 SOP，可以直接当我们模板的骨架。

1. 登记对标与本轮问题（给 REF-ID，不写真名） 2. 测量：脚本测时长、切点、镜长，出代表帧拼图 3. 看与读：按 8 个维度逐项记（观察 / 解释 / 未知） 4. 提炼机制：写成机制候选，单一来源不进库 5. 和本项目对照：并排差距表，逐条问是不是有意为之 6. 出片验证：同一模型生成前后两版，同一把尺子再量 7. 写报告与学习记录，下一轮先读这份
机制候选的固定格式：观众状态 / 戏剧问题 / 可选机制 / 可见效果 / 适用条件 / 失效边界 / 不得复制的部分。
只在一部剧里出现的做法标「单一来源」，不进机制库 —— 这一条能防止把偶然当规律。

03拆解的 8 个维度

每项都分三层写：直接观察（几秒、几次、什么画面）、解释（解决观众什么问题）、未知（测不出或样本不够的地方）。

维度具体记什么
系列与集长结构总集数、第 1 集与之后各集时长；前几集是否加长、加长段完成了什么；之后是否近似定长（定长说明是长母版切的，靠连播不是靠单集钩子）
开场第一帧与第一句的秒数；开场类型（当面受压 / 进行中的危机 / 旁白压前情 / 结果提前 / 旁人议论）；主角身份、处境、目标各在第几秒交代
信息载体旁白 / 画面文字（名条、系统面板）/ 对白里的说明 / 插入镜物证，各用在什么时候
对白密度与静默有声占比、每发声秒字数、最长静默出现在什么戏；一人一句来回还是长段独白
镜头语法平均镜长、超 4 秒镜头占比；景别分布；对话怎么拍；权力关系怎么落在调度上
集尾与下一集怎么接最后一句性质（问句/威胁/揭示/被打断）；末句后留几秒；下一集是接着说、换场还是复述
画幅与制作形态横竖屏、写实/三维/二维；人物脸型与光线风格是否全剧统一

04可直接当对照尺的实测基准

库里附了一组真实测量（9 部三维国漫风 AI 漫剧，2026-11）。注意：这是该形态的参照，不是质量线，别直接套到竖屏写实剧上。

指标实测区间怎么用
第 1 集时长中位约 134 秒首集普遍加长，用来立人设和建冲突
之后各集中位 36–63 秒正片单集比想象中短得多
平均镜长中位 1.9–3.9 秒打斗特效段可短到 1 秒内
有声占比0.65–0.84漫剧靠声音往前推，静默不能太多
语速每发声秒 3.9–5.8 字古装权谋可慢到约 2.8 字
末句后留白中位 < 1.2 秒集尾几乎不停，直接切下一集
系统流金手指全部在第 1 集前 30 秒内出声系统流不能拖到后面才交代

05质量门：可以直接改成你的终审清单

大纲 · 14 道门

  • 主角组 1–5 人、重要配角 ≤ 10
  • 主场景上限随集数动态（60 集 → 10）
  • 叙事道具 ≤ 8 件
  • 爽点间隔 ≤ 3 集，不能真空
  • 第 1 集必须有钩子
  • 大爆点不压最后一集
  • 每集三栏齐全、三人同框有拆解
  • 叙述体，不能带引号对白

剧本 · 10 道门

  • 每集时长在目标 ±15% 内
  • 单句台词 ≤ 35 字
  • 说话人必须合法（本场人物或 VO）
  • 钩子具象在前 3 拍内兑现（冷开场）
  • 每场至少一个动作节拍——纯对白场是广播剧
  • 爽点必须认领，防止改着改着改丢
  • 角色 / 场景 / 光照 / 道具对账上游
shuohao 的核心原则：剧本管戏，分镜管拍。台词是结构化数据（说话人 + 台词 + 语气），动作是独立节拍——这样台词能直接对接 TTS，动作节拍能直接喂生成。

07建议的搬用顺序

顺序搬什么搬到哪
1breakdown 的 7 步工作流 + 8 拆解维度直接当我们《爆款拆解 SOP 模板》的骨架
2实测基准表对照自己剧的时长、镜长、语速是否离谱
3outline 的「爽点间隔 ≤ 3 集」、script 的「每场至少一个动作节拍」「钩子前 3 拍兑现」写进剧本终审清单
4机制候选格式（含「单一来源不进库」）案例库的结论写法，防止把偶然当规律
